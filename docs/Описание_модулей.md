# TickTick: модули, файлы и связи

Клиент-серверное SPA. Браузер открывает React-приложение (`Front`), оно вызывает REST API (`Backend`), API читает и пишет PostgreSQL. Общая схема:

```
Браузер
  └─ Front (Vite + React)
        main.jsx → App.jsx (маршруты)
          ├─ store/authStore.js     сессия: JWT, роль, имя
          ├─ api/client.js          Axios, Bearer, автообновление токена
          ├─ pages/*                экраны, запросы к /api/*
          └─ components/*           куски интерфейса без своих запросов
                │  HTTP JSON (camelCase)
                ▼
        Backend (FastAPI, uvicorn :8000)
          main.py
            ├─ routers/*            HTTP-эндпоинты
            ├─ deps.py              JWT, текущий пользователь, роль admin
            ├─ schemas.py           тела запросов и ответов
            ├─ services/*           токены, wiki-ссылки, экспорт DOCX/PDF
            ├─ models.py            таблицы SQLAlchemy
            └─ db.py + config.py    пул PostgreSQL и настройки из .env
                │
                ▼
        PostgreSQL (ticktick_db)
          ticktick_schema.sql       таблицы, индексы, поиск, триггеры
          alembic/                  миграции поверх схемы
```

В режиме `npm run dev` Vite на порту 5173 проксирует `/api` и `/uploads` на `http://localhost:8000` (`Front/vite.config.js`). В Docker фронт собирается в статику и отдаётся nginx на порту 3000, а запросы идут напрямую на API (`VITE_API_URL=http://localhost:8000`).

JSON между фронтом и API в camelCase: схемы наследуют `CamelModel` (`alias_generator=to_camel`). В Python поля остаются в snake_case (`display_name`), в JSON уходят как `displayName`.

## Backend

Точка входа — `Backend/app/main.py`. Он создаёт приложение FastAPI, включает CORS из `settings.cors_origins`, раздаёт папку загрузок по `/uploads` и подключает восемь роутеров. Эндпоинт `GET /health` возвращает `{"status": "ok"}`. Интерактивная документация: `http://localhost:8000/docs`.

Зависимости перечислены в `Backend/requirements.txt`: FastAPI, uvicorn, SQLAlchemy, psycopg2, python-jose (JWT), passlib/bcrypt, pydantic-settings, python-docx, fpdf2, Alembic.

Образ API — `Backend/Dockerfile` (Python 3.12, шрифт DejaVu для PDF с кириллицей).

### Ядро `Backend/app`

| Файл | Что делает | С кем связан |
|------|------------|--------------|
| `__init__.py` | Пакет `app` | Импортируется uvicorn как `app.main:app` |
| `config.py` | Класс `Settings`: URL БД, секрет и аудитория JWT, срок access (15 мин) и refresh (30 дней), каталог `uploads`, список CORS. Читает `Backend/.env` | Его использует `db.py`, `deps.py`, `tokens.py`, `notes.py`, `main.py` |
| `db.py` | Движок SQLAlchemy, фабрика сессий `SessionLocal`, базовый класс моделей `Base`, генератор `get_db()` (сессия на один запрос, затем `close`) | Модели наследуют `Base`. Роутеры получают сессию через `deps.DbSession` |
| `models.py` | ORM-таблицы: `User`, `RefreshToken`, `Note`, `NoteLink`, `NoteAttachment`, `CalendarEvent`, `Todo`, `SyncCheckpoint` | Роутеры и сервисы работают с этими классами. Схема колонок совпадает с `ticktick_schema.sql` |
| `schemas.py` | Pydantic-модели запросов и ответов: auth, профиль, админ, заметки, задачи, события | Роутеры объявляют `response_model` и принимают тело запроса этими классами |
| `deps.py` | Разбор JWT (`HTTPBearer`), `get_current_user_id`, `get_current_user` (живой пользователь без `deleted_at`), `require_admin`. Алиасы `DbSession`, `UserId`, `CurrentUser`, `AdminUser` | Все защищённые роутеры зависят от них. Секрет и issuer/audience берутся из `config.py`, проверка — `python-jose` |
| `main.py` | Сборка приложения | Подключает роутеры и статику `/uploads` |

Почти каждый запрос к данным идёт так: роутер → зависимость из `deps.py` (сессия и пользователь) → модель из `models.py` → при необходимости сервис → ответ по схеме из `schemas.py`.

### Роутеры `Backend/app/routers`

Каждый файл объявляет `APIRouter` со своим префиксом. `main.py` подключает их все.

| Файл | Префикс | Эндпоинты | Логика |
|------|---------|-----------|--------|
| `auth.py` | `/api/auth` | `POST /register`, `/login`, `/refresh`, `/logout` | Регистрация и вход через `tokens.py`. Refresh хранится в `refresh_tokens` только как SHA-256. При обновлении старый refresh помечается `revoked`, выдаётся новая пара. Logout отзывает refresh |
| `users.py` | `/api/users` | `GET /me` | Профиль текущего пользователя (`CurrentUser` → `UserProfileDto`) |
| `admin.py` | `/api/admin` | `GET /stats`, `GET /users`, `PATCH /users/{id}/role`, `DELETE /users/{id}` | Только `AdminUser`. Статистика считает живых пользователей и неудалённые заметки, задачи, события. Смена роли — `user` или `admin`, себя понизить нельзя. Удаление пользователя — soft delete (`deleted_at`), себя удалить нельзя |
| `notes.py` | `/api/notes` | список, `?tag=`, `/trash`, `/search`, `GET/POST`, `PUT/DELETE /{id}`, `POST /{id}/restore`, `DELETE /{id}/permanent`, `POST /{id}/attachments` | Заметки только своего `user_id`. Создание и правка вызывают `wiki_links.sync_links`. Поиск — SQL-функция `search_notes`. Вложение пишется в `uploads/{user_id}/` и строка в `note_attachments` |
| `todos.py` | `/api/todos` | список (`done`, `priority`), `/overdue`, CRUD, `PATCH /{id}/toggle` | Приоритет 1–3. Удаление — `is_deleted = true`. Задача может ссылаться на заметку (`linked_note_id`) |
| `calendar.py` | `/api/calendar` | список (`from`, `to`), CRUD | Фильтр по пересечению интервала. `end_at` не раньше `start_at`. Удаление мягкое. Событие может ссылаться на заметку |
| `sync.py` | `/api/sync` | `GET ?since=&device_id=` | Отдаёт заметки, события и задачи пользователя, изменённые после `since`, и обновляет `sync_checkpoints`. Фронт этот эндпоинт не вызывает: он нужен внешнему клиенту синхронизации |
| `export_router.py` | `/api/notes/{note_id}/export` | `GET /docx`, `GET /pdf` | Находит заметку владельца и отдаёт файл через `export_service`. Имя файла в `Content-Disposition` поддерживает кириллицу (`filename*`) |

`__init__.py` в пакете роутеров пустой: импорт идёт по модулям из `main.py`.

### Сервисы `Backend/app/services`

| Файл | Кто вызывает | Что делает |
|------|--------------|------------|
| `tokens.py` | `auth.py`, косвенно `deps.py` (тот же claim и настройки) | Хеш пароля bcrypt, проверка пароля, access JWT (HS256, claim идентификатора пользователя, email, имя, роль), случайный refresh, SHA-256 хеш refresh, срок жизни refresh |
| `wiki_links.py` | `notes.py` после create/update | Ищет в тексте `[[Название]]`, удаляет старые исходящие `note_links` и создаёт новые на заметки того же пользователя с совпавшим заголовком |
| `export_service.py` | `export_router.py` | Снимает markdown-разметку и собирает DOCX (`python-docx`) или PDF (`fpdf2`). Для PDF подключает TTF с кириллицей: DejaVu в Linux-образе или Arial в Windows |

`__init__.py` пакета сервисов пустой.

### База данных и миграции

Схема создаётся скриптом `Backend/ticktick_schema.sql` (при первом старте контейнера Postgres он монтируется в `docker-entrypoint-initdb.d`).

| Таблица | Смысл | Связи |
|---------|-------|--------|
| `users` | Учётная запись: email, хеш пароля, имя, роль `user`/`admin`, мягкое удаление | Корень. На неё ссылаются все пользовательские сущности |
| `refresh_tokens` | Хеш refresh, срок, флаг `revoked` | `user_id → users`, CASCADE |
| `notes` | Заголовок, текст, теги `text[]`, корзина, `version`, `search_vector` | `user_id → users`. Триггер обновляет `updated_at` и вектор полнотекстового поиска (русский) |
| `note_links` | Ребро вики-графа | `source_note_id`, `target_note_id → notes`, уникальная пара |
| `note_attachments` | Имя, путь, MIME, размер файла | `note_id → notes` |
| `calendar_events` | Интервал, цвет, весь день, мягкое удаление | `user_id → users`, необязательный `linked_note_id → notes` |
| `todos` | Заголовок, приоритет 1–3, срок, выполнено, мягкое удаление | `user_id → users`, необязательный `linked_note_id → notes` |
| `sync_checkpoints` | Последняя синхронизация устройства | Уникальная пара `(user_id, device_id)` |

Поверх схемы лежат представление активных заметок `v_active_notes`, корзина `v_trash` и функция `search_notes(query, user_id)`: `websearch_to_tsquery` + `ts_headline`. Её вызывает только `notes.py` (`GET /api/notes/search`).

Alembic (`Backend/alembic.ini`, `Backend/alembic/env.py`) берёт URL из `settings` и метаданные моделей. Единственная ревизия `alembic/versions/20260316_01_add_user_role.py` добавляет колонку `users.role`, если таблицы уже есть, а колонки ещё нет. В Docker команда сервиса `api` гоняет `alembic upgrade head` перед uvicorn.

Скрипты:

- `Backend/scripts/init_db.ps1` — пересоздаёт volume Postgres через Docker Compose, поднимает `db` и `api`.
- `Backend/scripts/create_db_pgadmin.sql` — создание БД вручную в pgAdmin, если Docker не используется.
- `Backend/.env.example` — образец переменных. Рабочий `Backend/.env` в git не коммитится по смыслу конфигурации; приложение читает его через `config.py`.

## Front

Сборка — Vite (`Front/vite.config.js`, `Front/package.json`). Стек: React 18, React Router 6, Ant Design 5 (русская локаль), Zustand, Axios, dayjs. Точка HTML — `Front/index.html`, она монтирует `#root` и подключает `/src/main.jsx`.

Образ — `Front/Dockerfile`: сборка Node, раздача `dist` через nginx (`Front/nginx.conf`).

### Запуск и сессия

| Файл | Роль | Связи |
|------|------|-------|
| `src/main.jsx` | `ReactDOM.createRoot`, `ConfigProvider` (ru), `BrowserRouter`, рендер `App` | Корень дерева |
| `src/App.jsx` | Таблица маршрутов | Страницы, `ProtectedRoute`, `AdminRoute`, `AppLayout`, `useAuthStore` |
| `src/store/authStore.js` | Zustand + `persist` в `localStorage` под ключом `ticktick-auth`: `accessToken`, `refreshToken`, `userId`, `displayName`, `role`. Методы `setSession` и `logout` | Пишут страницы входа и регистрации. Читают меню, охранники маршрутов и `api/client.js` |
| `src/api/client.js` | Экземпляр Axios `http`. В запрос подставляет `Authorization: Bearer`. На 401 один раз вызывает `POST /api/auth/refresh`, кладёт новую сессию в store и повторяет запрос; если refresh не удался — `logout`. `apiGet` и `apiSend` возвращают тело ответа и превращают ошибку сервера в `Error` | Все страницы ходят в API только через этот файл |

`baseURL` берётся из `VITE_API_URL`. В dev он пустой, поэтому браузер бьёт в тот же origin, а Vite проксирует на API.

## Как проходят типичные сценарии

**Вход.** `LoginPage` шлёт email и пароль на `POST /api/auth/login`. `auth.py` ищет пользователя, `tokens.verify_password` сверяет bcrypt, `_issue_tokens` пишет хеш refresh в `refresh_tokens` и возвращает access JWT. `setSession` кладёт пару токенов и роль в Zustand (и в `localStorage`). `ProtectedRoute` пропускает на `/`, `SideMenu` показывает админку только если `role === "admin"`.

**Любой запрос после входа.** `client.js` добавляет `Bearer`. `deps.get_token_payload` проверяет подпись, issuer и audience. `get_current_user` достаёт `users` по id из токена и отсекает удалённых. Роутер фильтрует строки по `user_id`, поэтому пользователь видит только свои заметки, задачи и события.

**Истёк access.** Ответ 401. Интерцептор один раз вызывает `POST /api/auth/refresh`. Сервер находит хеш, проверяет срок и `revoked`, гасит старый токен и выдаёт новый. Клиент повторяет исходный запрос. Если refresh тоже недействителен, store очищается и пользователь оказывается на странице входа.

**Заметка и вики-ссылка.** `NotesPage` создаёт пустую заметку и открывает `NoteDetailPage`. Сохранение — `PUT /api/notes/{id}`. Если в тексте есть `[[Другая заметка]]`, `wiki_links.sync_links` пересобирает исходящие строки `note_links`. Ответ `NoteDto` содержит `outgoingLinks` и `incomingLinks`.

**Поиск.** Поле `SearchBar` на `NotesPage` через 300 мс вызывает `GET /api/notes/search?q=`. Роутер выполняет `search_notes` в Postgres и возвращает заголовок, фрагмент и ранг. `NoteList` показывает сниппет.

**Экспорт.** Кнопки DOCX и PDF на `NoteDetailPage` качают blob с `/api/notes/{id}/export/...`. Роутер проверяет владельца, `export_service` собирает файл.

**Задачи и календарь.** Отдельные страницы и таблицы. Общая точка — необязательная ссылка `linked_note_id` на `notes` (в текущем UI формы её не заполняют, поле есть в API и в моделях). Главная страница только считает длины списков этих же эндпоинтов.

**Админ.** `AdminPage` читает `/api/admin/stats` и `/api/admin/users`. Смена роли и удаление идут в `admin.py`, который опирается на `require_admin`. На клиенте пункт меню и маршрут дополнительно спрятаны по роли из store; настоящая проверка — на сервере.

**Выход.** `ProfilePage` отзывает refresh через `POST /api/auth/logout`, затем чистит store и уходит на `/auth/login`.

## Что с чем связано коротко

- Фронт не импортирует Python и не ходит в Postgres. Единственный контракт — HTTP `/api/*` и файлы `/uploads`.
- Страницы зависят от `api/client.js` и от компонентов. Компоненты зависят от страниц только через props.
- `authStore` — единственное клиентское состояние, которое живёт между страницами. Списки заметок и задач каждая страница держит у себя.
- Роутеры не вызывают друг друга. Общие вещи вынесены в `deps`, `schemas`, `models`, `services`.
- `notes` — центр данных: на них ссылаются `note_links`, `note_attachments`, опционально `todos` и `calendar_events`. Пользователь — центр владения: у каждой сущности есть `user_id`.
- Синхронизация (`sync.py`, таблица `sync_checkpoints`) и загрузка вложений (`POST /api/notes/{id}/attachments`) реализованы на API. Текущие страницы React их не вызывают.
